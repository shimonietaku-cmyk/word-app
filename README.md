# WordClimb 英単語

東京書籍『NEW HORIZON English Course 1・2』巻末「単語・連語のチェック」全1,961語を、
スマホで学習するアプリです。**学校のテストで点を取ること**を目的にしています。

- **テスト対策モード**（主役）… 出題範囲を「◯番〜◯番」で指定し、範囲内を1周ずつ確実に回す
- **熟語モード** … `get up`・`be good at 〜` のような熟語192個だけを、例文の穴うめや前置詞の選択で何周も回す
- **毎日モード**（副次）… 忘れかけた頃に出す方式で、長期的に積み上げる
- サーバーもログインもありません。**学習の記録はスマホの中だけ**に保存されます
- 他人との比較・ランキングはありません。ライフやハートで学習が止まる仕組みもありません
- 1日の出題数に上限はありません。やった分がそのまま実績として記録されます
- 広告・課金はありません
- ホーム画面に追加すると、電波がなくても使えます

## 1. パソコンで動かしてみる

### 用意するもの

**Node.js**（このアプリを動かすための土台）が必要です。
入っていない場合は https://nodejs.org/ja から「LTS」と書かれたほうをダウンロードして入れてください。

入っているかどうかは、次のコマンドで確認できます。バージョン番号が表示されればOKです。

```bash
node -v
```

### 手順

**手順1.** このフォルダを開いた状態で、必要な部品を取り込みます（最初の1回だけ。数分かかります）

```bash
npm install
```

**手順2.** アプリを起動します

```bash
npm run dev
```

**手順3.** 画面に出てきた `http://localhost:5173/word-app/` のようなアドレスを、
ブラウザ（Chrome、Edge など）のアドレス欄に入れて開きます。

止めるときは、コマンドを打った画面で `Ctrl` + `C` を押します。

### スマホの見え方で確認する

Chrome でアプリを開いた状態で `F12` キーを押し、
左上のスマホのマーク（📱）をクリックすると、スマホの縦画面サイズで表示できます。

## 2. インターネットに公開する（GitHub Pages）

GitHub という無料のサービスに置いて、URLを渡すだけで使えるようにします。

### 手順1. GitHub のアカウントを作る

https://github.com/ で「Sign up」からアカウントを作ります（無料）。

### 手順2. 置き場所（リポジトリ）を作る

1. GitHub にログインして、右上の「+」→「New repository」
2. **Repository name** に `word-app` と入力
   - ⚠️ **別の名前にする場合は、後述の「リポジトリ名を変えたとき」も必ず読んでください**
3. **Public**（公開）を選ぶ
   - Private（非公開）だと GitHub Pages が使えない場合があります
4. 「Create repository」を押す

### 手順3. このフォルダを GitHub に送る

パソコンで、このフォルダを開いた状態で次のコマンドを順番に実行します。
`あなたのユーザー名` の部分は、自分の GitHub のユーザー名に置き換えてください。

```bash
git init
```

```bash
git add .
```

```bash
git commit -m "英単語学習アプリ"
```

```bash
git branch -M main
```

```bash
git remote add origin https://github.com/あなたのユーザー名/word-app.git
```

```bash
git push -u origin main
```

（初回はブラウザが開いて GitHub のログインを求められます）

### 手順4. GitHub Pages を有効にする

1. GitHub でさっき作ったリポジトリのページを開く
2. 上のメニューの「**Settings**」→ 左側の「**Pages**」
3. **Source** の欄で「**GitHub Actions**」を選ぶ

これで設定は完了です。

### 手順5. 公開されるのを待つ

リポジトリの「**Actions**」タブを開くと、公開処理が動いています。
緑のチェックマーク（✓）になれば完了です（3〜5分ほど）。

公開先のURLはこちらです：

```
https://あなたのユーザー名.github.io/word-app/
```

以後、ファイルを変更して `git push` するたびに、自動で最新版に更新されます。

### リポジトリ名を変えたとき

`word-app` 以外の名前にした場合は、**2か所**を書き換えてください。

`vite.config.ts` の8行目あたり：

```ts
const REPO_NAME = 'word-app';   // ← ここを新しいリポジトリ名にする
```

書き換えたら、もう一度 `git add .` → `git commit -m "リポジトリ名を変更"` → `git push` します。

## 3. スマホで使う

公開したURLをお子さんのスマホに送り、ブラウザで開きます。

**ホーム画面に追加すると、アプリのように使えて電波がなくても動きます。**

- **iPhone（Safari）**：下の「共有」ボタン（□に↑）→「ホーム画面に追加」
- **Android（Chrome）**：右上の「⋮」→「ホーム画面に追加」

### 発音が鳴らないとき

まず **設定 →「🔊 音声の診断」** を開いて「テスト再生」を押してください。
この端末で何が起きているか（音声データの有無、エラーの内容）が表示され、
「結果をコピー」でそのまま共有できます。

よくある原因：

- 設定の「発音を鳴らす」がオフになっている
- iPhone：本体の**消音スイッチ**がオンになっている
- **Android：音声エンジンや英語の音声データが入っていない**
  → 端末の「設定 → システム → 言語と入力 → 音声出力（テキスト読み上げ）」で
  Google テキスト読み上げエンジンと英語の音声データをインストールしてください

## 4. 単語データを差し替える

単語は `public/data/words.json` に入っています。ここを差し替えれば内容を変えられます。

### データの形

```json
[
  {
    "id": "g1-unit-1-0001",
    "grade": 1,
    "unit": "Unit 1",
    "part": 1,
    "section": "unit",
    "en": "basketball",
    "ja": ["バスケットボール"],
    "jaMain": "バスケットボール",
    "type": "word",
    "pos": "noun",
    "level": 3,
    "note": "",
    "srcPage": "y1_p1"
  }
]
```

| 項目 | 意味 |
|---|---|
| `id` | 単語ごとの重複しない名前。**変えると学習記録がリセットされます** |
| `grade` | 学年（1 または 2） |
| `unit` | 単元名。**並び順はこのファイルの上から順に画面に出ます**（教科書順にしてください） |
| `part` | パート番号。無ければ `null` |
| `en` | 英語。`〜` `[ ]` `( )` を含んでもOK（採点時に自動で取り除かれます） |
| `ja` | 日本語訳の一覧 |
| `jaMain` | 4択に使う代表の訳 |
| `pos` | 品詞。誤選択肢を選ぶときに使います |
| `level` | 難易度（1〜3） |
| `note` | 補足（「meet の過去形」など）。無ければ `""` |

### 差し替えの手順

1. 新しい `words.json` を `public/data/words.json` に上書きコピーする
2. 確認する

```bash
npm test
```

3. 問題なければ公開する

```bash
git add . ; git commit -m "単語データを更新" ; git push
```

⚠️ **注意**：`id` を変えると、その単語の学習記録は無くなります（新しい単語として扱われます）。
差し替え前に、アプリの「設定 → 進捗を書き出す」でバックアップを取っておくと安心です。

### 熟語の例文データ（`public/data/idioms.json`）

熟語モードで使う例文です。`words.json` の `type: "phrase"` と `id` で1対1に対応しています。

```json
[
  {
    "id": "g1-unit-3-0037",
    "en": "get up",
    "kind": "idiom",
    "q": "I ___ at six every morning.",
    "a": "get up",
    "ja": "私は毎朝6時に起きます。"
  }
]
```

| 項目 | 意味 |
|---|---|
| `id` | `words.json` の同じ熟語の `id`。ここが合っていないとその熟語は出題されません |
| `en` | 見出し。`words.json` の `en` と同じにします |
| `kind` | `idiom`（熟語）または `compound`（`post office` のような2語で1つの名詞） |
| `q` | 例文。空所は `___`（アンダースコア3つ）。空所は2つ以上あってもかまいません |
| `a` | 空所に実際に入る形。空所が複数なら `\|` 区切りで前から順に（例：`not\|very much`） |
| `ja` | 例文の和訳 |

`npm test` が、全件について「空所の数と `a` の数が合っているか」「和訳があるか」
「4択に答えが2つ入っていないか」を確かめます。`words.json` を差し替えたときは、
このファイルの `id` も合わせて更新してください（対応が取れない熟語は自動的に出題から外れます）。

## 5. アプリの中身のしくみ

### フォルダの構成

```

├─ public/data/words.json    単語データ（1,961語）
├─ public/data/idioms.json   熟語の例文データ（243件。words.json の phrase と1対1）
├─ src/
│  ├─ lib/                  学習のしくみ（計算だけを行う部分。テスト済み）
│  │  ├─ drill.ts            テスト対策の範囲・周回・出題順（網羅保証はここ）
│  │  ├─ idioms.ts           熟語モードの出題づくりと周回
│  │  ├─ distractors.ts      4択の「まちがいの選択肢」を作る
│  │  ├─ judge.ts            綴りの採点（表記のゆれをそろえる）
│  │  ├─ scheduler.ts        次にいつ復習するかを決める（ts-fsrs）
│  │  ├─ session.ts          毎日モードの1回ぶんを組み立てる
│  │  ├─ stage.ts            出題形式の昇格・降格を決める
│  │  ├─ streak.ts           連続学習日数
│  │  ├─ storage.ts          記録の保存と読み込み
│  │  ├─ stats.ts            記録画面の集計
│  │  └─ speech.ts           発音の読み上げ
│  ├─ components/           画面の部品
│  └─ screens/              各画面
│     ├─ Home.tsx            ホーム（テスト対策が主役、毎日モードが副次）
│     ├─ DrillSetup.tsx      テスト範囲の指定（番号入力・プリセット）
│     ├─ DrillSession.tsx    テスト対策の出題
│     ├─ DrillList.tsx       範囲内の単語を番号順に一覧
│     ├─ IdiomSetup.tsx      熟語モードの設定（学年・出題形式）
│     ├─ IdiomSession.tsx    熟語モードの出題
│     ├─ IdiomList.tsx       熟語ごとの状況と例文の一覧
│     ├─ Session.tsx         毎日モードの出題
│     └─ SpeechDiagnostics.tsx  音が出ないときの診断
└─ .github/workflows/       GitHub Pages への自動公開の設定
```

### 学習のしくみ（要点）

**テスト対策モード（ホームの一番上）**

学年（1年／2年）を選び、単語番号で範囲を指定します。番号は教科書の巻末リストの並び順で、
**1年は1〜1115番、2年は1〜846番**と学年ごとに1から振られます。

- 範囲内の全単語を1つの「順番待ちの列」に入れ、使い切るまで補充しません。
  そのため**1周終わるまで同じ単語は絶対に出ません**（運まかせではなく、仕組みとして保証）
- 1周終わると「この範囲を1周しました」と表示され、そのまま2周目に入れます
- **2周目以降は、間違えた単語の出題回数が増えます**（直前に間違えた語は3回、過去に間違えた語は2回）。
  ただし連続で出ないよう、周の中で間隔を空けて配置します
- 出題中は「12 / 50問」と正解数・不正解数が常に見えます
- 終了時に正答率と間違えた単語一覧が出て、**その単語だけをもう一度**回せます
- 「単語ごとの状況」で、範囲内の全単語を番号順に一覧できます（未出題／正解／不正解／連続正解数）
- よく使う範囲は名前を付けて保存でき、次回1タップで呼び出せます
- 範囲と途中経過は保存されるので、**次に開いたとき続きから再開**できます

**熟語モード**

熟語（`look for 〜`・`get up` など）は、単語と覚え方が違います。
かたまりで意味が決まり、とくに前置詞（in / at / for …）を間違えやすく、
「文の中でどう使うか」まで見ないとテストで書けません。
そこで単語のドリルとは別の仕組みにしてあります。

- 対象は `words.json` の `type: "phrase"` 全243件。うち**熟語192個**と、
  `post office`・`New York` のような**2語で1つの名詞51個**に分けてあり、既定は熟語だけです
- 全部で240個ほどしかないので、範囲は番号で切らず**学年（1年／2年）だけ**を選びます
- 出し方はテスト対策と同じ「順番待ちの列」方式なので、**1周終わるまで同じ熟語は出ません**。
  2周目以降は間違えた熟語ほど多く出ます
- 熟語1つにつき**短い例文と和訳**を1件ずつ用意してあり（`public/data/idioms.json`）、
  答え合わせでは必ず「その熟語が入った文まるごと」を見せます

出題は4つの形式があり、「おまかせ」を選ぶと**正解を重ねるほど難しくなります**。

| 形式 | 出題のしかた | 例 |
|---|---|---|
| 1. 意味 | 熟語を見て日本語を4つから選ぶ | `have to 〜` → 〜しなければならない |
| 2. 例文の穴うめ | 和訳に合うよう、文の空所に入る熟語を選ぶ | `You should ___ after school.` → `go straight home` |
| 3. 前置詞ドリル | 熟語の一部（多くは前置詞）を選ぶ | `be good ___ 〜` → `at`（誤：in / up / above） |
| 4. 日本語から英語 | 意味を見て熟語を選ぶ | 〜が上手だ → `be good at 〜` |

まちがえると次はまた1に戻るので、あやふやな熟語ほどやさしい形からやり直せます。

**まちがいの選択肢は「1語目が同じ熟語」から取る**

`get ready` の誤選択肢は `get up` / `get off` / `get to 〜`、
`be good at 〜` の前置詞ドリルの誤選択肢は他の熟語で実際に使われている前置詞から選びます。
また、訳が同じ・訳が含み合う熟語（`take a picture` と `take a photo`、`少し` と `ほんの少し`）は、
どちらを選んでも正しく読めてしまうため、誤選択肢に**入れません**。

**熟語モードは復習日（FSRS）を動かしません**

短時間で何周も回す使い方をするので、混ぜると毎日モードの復習日がずれてしまいます。
回答数と正答数だけは「今日の実績」に足されるので、連続学習日数には反映されます。

**3段階で少しずつ難しくする（両モード共通）**

| 段階 | 出題のしかた | 次の段階に上がる条件 |
|---|---|---|
| 1. 受容 | 英語を見て、日本語を4つから選ぶ | 2回続けて正解 |
| 2. 想起 | 英語だけを見て頭の中で答え、めくって自己判定 | 2秒以内の正解が2回 |
| 3. 産出 | 日本語を見て英語を作る（文字を並べる → 慣れたらキーボード入力） | — |

まちがいが2回続いたら、1つ前の段階に戻ります（難しすぎて止まらないように）。

**まちがいの選択肢は「わざと紛らわしく」作る**

同じ単元の同じ品詞、綴りが似ている語（`quiet` と `quite` など）を優先して選びます。
当てずっぽうで当たらないようにすることで、記憶に残りやすくなります。

**復習のタイミングは自動で決まる**

`ts-fsrs` という、記憶の研究にもとづいたライブラリが「次にいつ出すか」を計算します。
Again / Hard / Good / Easy をお子さんに選ばせると迷って止まってしまうので、
**正解かどうかと解答にかかった時間から自動で判定**します。

**1日の出題数に上限はありません**

テスト直前に集中してやりたいことがあるため、上限で止める仕組みは入れていません。
代わりにホーム上部へ「今日 87問 / 正答率 72%」のように実績を表示します。

**最後は満点で終われるようにする（毎日モード）**

セッション中にまちがえた単語は、そのセッションの最後にもう一度出します（最大3周）。
この出し直しぶんは成績の計算には入れないので、実力を高く見せることはありません。

### テストを動かす

```bash
npm test
```

`src/lib/` の計算部分に対して 136 件のテストがあります。
本物の `words.json` 1,961語を使った確認（全語で4択が作れるか、速度は十分かなど）も含まれます。
とくに「1周のあいだ同じ単語が2回出ない」ことは、乱数を20パターン変えて毎回確かめています。

### 公開用のファイルを作る

```bash
npm run build
```

`dist` フォルダに出力されます（GitHub にpushすれば自動で行われるので、普段は不要です）。

## 6. 困ったときは

| 症状 | 対処 |
|---|---|
| `npm install` でエラーになる | Node.js が入っているか `node -v` で確認してください |
| 画面が真っ白 | ブラウザで `F12` を押し、「Console」に出ている赤い文字を確認してください |
| 公開したURLで真っ白 | `vite.config.ts` の `REPO_NAME` が、GitHub のリポジトリ名と同じか確認してください |
| Actions が赤い✗になる | 「Actions」タブでその実行をクリックすると、どこで失敗したか表示されます |
| スマホで内容が古いまま | ホーム画面のアイコンから開き直すか、ブラウザを一度閉じてから開いてください |
| 記録を消してしまった | 「設定 → 進捗を読み込む」で、書き出しておいたJSONファイルから戻せます |
